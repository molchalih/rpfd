# The numbers tools/docgate/docgate.sh checks itself against. They are
# measurements and one declaration, not preferences, and they are here rather
# than in the script so that moving one is a line in a diff a reviewer can argue
# with.
#
#   claims  the fewest path claims the extractor may find before the gate stops
#           believing itself. Lowering this is a claim about the documentation
#           and needs the measurement that supports it — the usual cause is the
#           script, not the docs.
#
#   bytes   the tracked Markdown surface, in bytes, measured by
#             git ls-files -z -- '*.md' | xargs -0 cat | wc -c
#           **Zero slack, deliberately.** The gate fails both above and below
#           this number, so it is a ratchet rather than a ceiling: every
#           documentation change is expected to move this line, and that is the
#           point. Headroom would be spent silently by whatever grew next, and
#           an unreviewed byte is exactly what a budget exists to prevent —
#           a ceiling nobody has looked at is not a measurement of anything.
#           The cost is one line in the diff of every documentation change,
#           which is the same line the change already owes a reviewer.
#
#   roots   the top-level entries of this repository that a command line inside
#           a fenced block may be rooted at. Declared here rather than derived
#           from `git ls-files`, because derived meant a renamed directory
#           stopped being a subject instead of being reported: every command
#           line naming `tools/` went unread the moment `tools/` was gone. The
#           gate fails when one of these stops naming a tracked directory, so
#           the rename is caught from both sides. A new top-level directory that
#           command lines name is added here in the change that adds it.
#
